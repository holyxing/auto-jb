## 2. 用户操作与执行范围

1. 用户在日常 Chrome 浏览器中安装扩展、登录 BOSS，打开上述指定搜索页面。
2. 点击“连接当前账号”，系统核对账号及页面布局。
3. 工作台展示“北京 AI产品经理搜索结果 / 逐岗判断 AI 与产品相关性”，其余岗位条件为空。搜索词只是候选来源，不是职位名称限制；无需重新创建或修改求职期望。
4. 用户点击“开始自动沟通与投递”。工作台说明将自动点击符合条件岗位的“立即沟通”，并在已验证的简历发送流程中使用站内已有简历。
5. 系统自动处理左侧全部符合范围的岗位，不按简历匹配分筛选 Top N；每个岗位完成或明确跳过后继续，当前批次处理完再向下滚动加载。
6. 用户通过工作台查看进展，必要时暂停、停止或接管；正常操作不逐岗位审批。

启动记录绑定账号、岗位/城市范围、动作范围、预算及可用的简历策略。若平台原生开聊动作会自动发送站内已配置的默认招呼，该副作用应在启动说明中呈现，纳入本次开聊授权；不要再额外生成或补发一条招呼。

只打开聊天且必须输入新文案才能真正发起沟通时，不编造内容或发送空消息；暂停该发送能力，提示需要一次性配置并授权固定文案。配置后复用该授权，不逐岗位询问。回复招聘方、交换联系方式、付费、新协议确认不在首版自动执行范围。

简历无需在开始沟通前强制重新选定。进入已验证的附件发送环节时，若已有明确绑定或唯一可选附件则复用；多个附件无默认项时首次选择一次，后续复用。不要把附件选择歧义升级为“所有岗位都不能读取或筛选”。

本文描述产品授权设计。编写文档和本地样本测试不意味着已经启动真实外部发送；真实账号执行须有用户明确启动的任务或同等明确指令。

### 执行预算的建议默认值

工程建议：一次最多进入 20 个合格岗位的执行流程，最长运行 30 分钟，任一达到即停止新增变更动作。数值可调整，必须在启动界面展示；属于工程建议，不是已确认需求、岗位筛选条件或平台安全额度。

岗位计数在资格核对通过并进入执行流程时增加，包括后来发现已沟通过、执行失败或暂停的岗位；不以成功次数作为唯一停止条件。已发出动作可继续只读核验，预算到期不再追加附件发送或新开聊。

“相关岗位都纳入”指指定搜索结果中已发现且符合范围的岗位不因名称、职级或分数被淘汰。预算只划分执行批次：保存未处理队列和列表锚点，用户继续任务时接着处理，不丢弃剩余岗位；不默认创建后台定时任务。尚未滚动发现的岗位不虚构为已入队，不将单轮完成表述为已投完全部相关岗位。

## 3. 页面区域与适配器契约

| 区域 | 读取内容 | 可执行动作 |
| --- | --- | --- |
| 搜索与筛选区 | 用户指定 URL 的搜索词、北京城市和空行业/职位筛选 | 打开指定 URL；若当前条件不同则提示切换，不额外轮询其他搜索词 |
| 左侧岗位列表 | 卡片稳定标识、标题、公司、地点、选中状态、可见加载提示 | 选择卡片、滚动实际驱动列表加载的容器 |
| 右侧详情 | 当前岗位身份、标题、工作地、职责、招聘人信息及按钮状态 | 在正确岗位详情内点击“立即沟通” |
| 点击后出现的沟通界面 | 会话对象、岗位上下文、消息/请求状态、可能存在的简历入口 | 已验证的原生开聊确认；条件满足时发送绑定简历 |

以上是逻辑区域，不是已知 DOM 选择器。实现前实际观察 DOM/可访问性信息确定容器、元素和区域边界，不写死截图坐标。

扩展使用用户提供的固定搜索 URL，不擅自修改保存的求职期望，也不循环搜索其他职位名称。当前搜索条件不一致时提供一键打开指定 URL。岗位相关性仍以标题及详情的实际含义为准，不把“AI产品经理”字面命中当作录用条件。

扩展最小接口：`observeListContext`、`readVisibleCards`、`selectCard`、`readDetail`、`scrollJobList`、`observeContactOutcome`、`restoreListContext`。简历能力使用单独的 `observeResumeCapability` 与 `sendBoundResume`，验证前不可调用发送。

## 4. 精准执行流程

| ID | 操作与前置条件 | 成功后 | 不满足时 |
| --- | --- | --- | --- |
| S01 | 检查账号、扩展、左右分栏和控制权；读取当前条件 | 创建任务，冻结范围、预算与可执行能力 | 登录失效或布局未知时暂停 |
| S02 | 打开用户指定的北京 AI产品经理搜索 URL，核对搜索条件 | 保存搜索入口、筛选和列表会话标识 | 条件不一致时提示切换，不盲用旧筛选 |
| S03 | 读取左侧当前可见卡片，按稳定岗位标识建立去重队列 | 依列表顺序取未处理卡片；总监、负责人或普通名称均保留详情判断机会 | 无稳定标识则待复核，不用 DOM 下标代替身份 |
| S04 | 保存列表锚点，点击目标卡片，等待右侧加载并核对岗位身份 | 确认右侧属于该卡片，再判断 AI 与产品相关性、北京及招聘状态 | 旧详情、错位、关键字段缺失或相关性无法确定时不点击沟通 |
| S05 | 检查本地开聊/附件记录、可见平台状态及未决动作；获取岗位锁 | 未沟通者进入 S06；已沟通者跳过重复开聊，按证据评估已有会话的附件步骤 | 有未决动作先只读核验；跨岗位会话不明则待复核 |
| S06 | 在已绑定的右侧详情定位“立即沟通”，重验上下文与按钮 | 持久化 CONTACT 意图，执行一次点击 | 禁用、遮挡、详情变化时重新观察或暂停；不盲重试 |
| S07 | 识别点击后分支，核对招聘人与岗位上下文；处理已验证的原生确认 | 分别记录聊天已打开、开聊已提交、已有沟通等结果 | 未知结果或未知弹窗暂停；不能把窗口打开当作发送成功 |
| S08 | 在正确会话只读检查简历能力；有明确入口、权限和简历绑定且能力已验证时执行发送 | 独立记录简历发送证据；暂不可发则记录等待/不可用，不伪造成功 | 需对方同意则等待；绑定歧义首次选择；发送结果不明则暂停 |
| S09 | 关闭已识别弹窗或返回原列表，重新读取账号、指定搜索入口、筛选、锚点和当前卡片 | 继续下一未处理卡片；当前可见批次耗尽后定向滚动左侧加载 | 恢复失败则暂停；预算到期保存待处理队列；明确无更多或列表无进展时结束本轮 |

### 4.1 左右区域同步：必须在开聊前验证

- 选中 A 卡片后，右侧可能仍显示 B 的旧详情；卡片高亮、固定延时或按钮仍存在都不证明详情更新成功。
- 优先比较卡片与详情实际暴露的稳定岗位 ID/链接身份。辅以标题、公司、地点及招聘人上下文核验；记录依据。
- 若未暴露相同 ID，可使用观察到的卡片详情关联以及唯一的组合身份验证；仅标题相同、仅公司相同或模型猜测不足以确定身份，存在歧义则不发起沟通。
- 每次选择递增 `selection_epoch`，详情快照绑定当前目标、页面及该序号。迟到的旧详情响应不得推进当前流程。
- 点击沟通前再次确认右侧详情身份、选中岗位及快照有效性。任何变化都使旧动作失效。

### 4.2 左侧滚动加载与恢复

- 识别实际驱动左侧岗位列表加载的滚动容器；不得默认滚动右侧详情或整页。若经观察确认由整页滚动触发列表加载，可采用该机制并验证新卡片出现。
- 使用持久化 `seen_job_ids` 与已处理记录，不用“第 N 张卡片”、DOM 节点引用或滚动像素位置作为岗位身份。
- 不假设列表一定是虚拟列表；按可能回收/复用 DOM 节点设计，每轮重新观察元素与岗位身份。
- 当前可见批次处理完后，保存最后稳定岗位锚点，滚动一段，等待加载变化及新岗位 ID，再处理新增项。重复推荐不重复开聊。
- 存在加载动画时先有界等待，不将短时空白视为列表结束。连续两轮完整等待后仍无新 ID，仅记录 LIST_NO_PROGRESS 并结束本轮，不宣称已遍历全部平台岗位。
- 有明确“没有更多”提示时记录 END_OF_VISIBLE_RESULTS；预算到期记录 BUDGET_REACHED。列表无进展不作为自动重载整页、换查询或重复点击的理由。
- 进入聊天前保存查询/期望入口、筛选、列表会话、锚点岗位、滚动位置和目标岗位。返回后重新读取、重新定位；锚点丢失时有界重扫并用稳定 ID 去重，不沿用旧坐标。
- 聊天可能是弹窗、同页面板或页面跳转。仅在实测确认对应分支后实现恢复动作，不默认浏览器“后退”必然正确。

### 4.3 宽范围语义判定：AI 相关且有产品职责

用户要求“与 AI 和产品相关”，按两者同时相关理解，不扩成任何 AI 岗位或任何产品岗位。依据标题和职责的完整语义判断，不要求职位名称含连续字串“AI产品经理”，也不要求同时出现字面关键词“AI”和“产品”。

- 纳入 AI 产品经理、AI 产品总监、AI 产品负责人、AIGC 产品、大模型产品、Agent/智能体产品、AI 平台产品等岗位；名称举例不是封闭白名单。
- 名称只是“产品经理”“产品总监”或其他名称，但职责明确涉及 AI 产品规划、需求、设计、落地、迭代或产品商业化，同样纳入。
- AI 产品运营、产品解决方案等相邻名称，只要实际承担 AI 产品相关职责也纳入；不因不是“经理”而排除。
- AI 可以通过人工智能、大模型、机器学习、智能体、AIGC 等语义体现；“智能”一词单独出现不能证明 AI 相关，应继续读详情。
- 不因总监/负责人职级、技术背景、薪资、经验、学历、行业或个人匹配分排除相关岗位。所有明确相关岗位依列表顺序进入自动处理，不只挑高分或前几个。
- 仅公司介绍提到 AI、通用要求提到“熟练使用 AI 办公”，而职位本身不涉及 AI 产品，不能因此纳入。纯算法研发、纯开发或纯销售且没有实际产品职责也不满足两者相关。
- 标题不足以判断时必须读右侧详情；缺少信息时标记 NEEDS_REVIEW，不将“名称未命中”作为拒绝理由，也不因简单词表未命中而淘汰。
- 工作地点仍须为北京或可明确归属北京的行政区；总部地点不代替工作地。多城市且未能绑定北京、仅远程或地点缺失时待复核。

应用层记录 `ai_related`、`product_related`、`evidence` 与 `decision`（INCLUDE / EXCLUDE / NEEDS_REVIEW）。Jev 返回限定选项、评分或命题判断，不生成自由文本：先由代码将标题/职责分成有编号的原文片段，Jev 判断相关性并可从片段编号中选择证据，最后由代码回填原文与来源位置。不得要求 Jev 直接撰写 evidence 或解释，也不得将无对应原文的理由保存为证据。组合决策由代码完成，矛盾或证据不足转待复核。模型评估的是岗位相关性，不是个人胜任力；语义明确相关即纳入，低置信度补读详情或待复核，不偷偷增加高分门槛。

| 示例 | 判定 |
| --- | --- |
| AI产品总监（技术背景）；北京，负责 AI 产品规划与落地 | INCLUDE |
| 大模型产品负责人 / AIGC产品经理 / 智能体产品运营；北京，确有产品职责 | INCLUDE |
| 标题“产品经理”；北京，职责为大模型应用产品设计与迭代 | INCLUDE，即使标题没有 AI |
| 标题“产品经理”；详情只是传统业务，无 AI 产品相关职责 | EXCLUDE |
| 算法工程师；职责仅训练模型，文案泛称“服务公司产品”或“与产品团队协同” | EXCLUDE，不把技术支撑或协作视作负责产品职责 |
| 技术专家；职责提到参与产品规划，但岗位主责不清 | NEEDS_REVIEW，不自动联系 |
| 标题“智能业务负责人”；详情尚未加载 | NEEDS_REVIEW，先补读，不按名称直接拒绝 |

### 4.4 “立即沟通”后的分支与简历发送

| 实测可能分支，当前均未验证 | 设计处理 | 可记录的结果 |
| --- | --- | --- |
| 打开聊天，未出现已发送消息或开聊提交证据 | 记录聊天已打开；若必须输入内容，等待一次性文案配置 | CHAT_OPENED，不是 CONTACT_INITIATED |
| 自动发出平台已配置默认招呼，或明确提交开聊请求 | 核对收件人与岗位，保存发送/请求证据，不追加第二条招呼 | CONTACT_INITIATED |
| 出现标准开聊确认窗口 | 在已冻结范围内自动确认，随后核验外部效果 | 根据证据记录 CONTACT_INITIATED 或 UNKNOWN |
| 打开已有会话/显示已沟通过 | 不重复首次招呼；核对当前岗位归属后评估简历状态 | ALREADY_CONTACTED；附件仍单独判断 |
| 正确会话中出现可用的简历发送入口 | 能力验证后复用已有绑定简历，独立记录 RESUME_SEND 意图并发送 | SENDING → SENT / FAILED / UNKNOWN |
| 页面明确说明需对方同意/回复才能发送附件 | 记录依赖，不重复申请、不轮询轰炸 | WAITING_PEER |
| 已知聊天布局下没有可用附件入口 | 记录本次不可用并继续其他岗位；后续有新状态再评估 | UNAVAILABLE，不是已发送 |
| 布局未知、限制提示、结果无法对应目标 | 暂停并保存必要证据，人工处理后重新观察 | UNKNOWN 或 WAITING_HUMAN |

若页面只提供“请求发送简历”，请求成功不等于附件发送成功；作为独立动作记录，在已确认该请求是原生简历流程且任务授权覆盖后才执行。一次请求之后等待站内条件变化，不自动重复。

初期可以验证并交付自动开聊能力，但必须标明附件能力尚未验证，不能据此宣称已完成自动简历投递。已有附件的发送流程属于后续需要验证的同一目标，不从产品范围中删除。

## 5. 状态、证据与去重

### 5.1 分开保存状态

- 任务：READY、RUNNING、PAUSED_USER、WAITING_HUMAN、COMPLETED、STOPPED、FAILED；结束原因另存。
- 资格：DISCOVERED、ELIGIBLE、SKIPPED、NEEDS_REVIEW。
- 沟通：NOT_STARTED、INITIATING、CHAT_OPENED、CONTACT_INITIATED、ALREADY_CONTACTED、FAILED、UNKNOWN。
- 简历：NOT_CHECKED、UNAVAILABLE、WAITING_PEER、READY、SENDING、SENT、ALREADY_SENT、FAILED、UNKNOWN。

各状态字段独立，不能将沟通成功直接赋值为简历 SENT。INITIATING/SENDING 崩溃恢复后先进入未决核验，证据不足时为 UNKNOWN。NOT_CHECKED 和 UNAVAILABLE 也必须区分：未检查不是已确认没有入口。

COMPLETED 仅表示本轮已结束并归档，可能仍有 WAITING_PEER 或 UNAVAILABLE 岗位；不得显示“全部投递成功”。没有证据证明本次动作成功时，不增加本次成功计数。

区分长期队列 `campaign_id` 与执行批次 `run_id`。上述任务状态属于 run；预算到期可结束本次 run，未处理岗位仍保留在 campaign。用户点击“继续”时创建关联前一批次的新 run，重新校验账号、页面、当前岗位条件与未决动作，再续接队列，不重新累计历史成功为本次成功。PAUSED_USER / WAITING_HUMAN 则在同一未结束 run 内恢复；停止的 run 不自行重启。

`seen_job_ids` 只表示发现过，不表示永久跳过。资格结论关联 `policy_version + job_snapshot_hash`；用户拓宽岗位范围或职责变化时，重评尚未成功处理的相关候选。历史实际沟通/附件账本跨版本保留，不能因重评而重复发送。动作待执行期间范围变化时，旧指令失效并按当前范围重验；用户意图未包含扩大范围时不得自行扩展。

### 5.2 证据等级

| 状态 | 最低证据要求 | 不足以成立的情况 |
| --- | --- | --- |
| CHAT_OPENED | 明确出现目标会话界面并能关联岗位/招聘人 | 仅按钮点击返回 |
| CONTACT_INITIATED | 目标岗位的明确开聊提交提示，或正确会话中新出现且已发送的原生招呼/已授权消息；排除发送中与失败 | 只打开窗口、旧消息、模型 DONE |
| ALREADY_CONTACTED | 页面已沟通状态或对应历史证据，能关联目标岗位 | 只因同公司/同招聘人存在其他岗位聊天 |
| SENT | 目标会话出现已发送的绑定附件记录或明确的简历发送成功记录，排除上传中/发送失败 | 在线简历可见、简历请求已发出、开聊成功 |
| ALREADY_SENT | 正确会话与简历的已有发送记录；不能算本次成功 | 不明历史附件、不同招聘人或不同岗位上下文 |
| UNKNOWN | 动作可能已产生效果，无法取得或关联明确证据 | 不得为了重试而直接改成 FAILED |

“继续沟通”“已沟通”等文案若在实测出现，只用于支持沟通状态，不能证明附件已发出。截图或文字是证据载体，仍需关联账号、岗位、招聘人、动作与时间，不能看到一个成功字样就计数。

### 5.3 持久化与恢复

- 岗位身份键为 `platform + account_id + stable_job_key`。`stable_job_key` 来源于可验证的岗位 ID/规范化入口身份，不能用列表下标替代。
- 分开登记 CONTACT、RESUME_REQUEST、RESUME_SEND 动作及证据；同岗位不能因附件变化而重新开聊，重复联系与重复附件发送分别去重。
- 记录 `conversation_id / recruiter_key`（页面可读时）作为辅助关联。同一招聘人可能对应多个岗位，不默认“一招聘人一岗位”；若共享会话导致岗位绑定不明，待复核，不盲发第二条招呼或附件。
- 单账号执行锁和岗位动作锁互斥。持久化动作意图后才执行可能产生外部效果的点击；意图中包括 `attempt_id / action_type / target / observation_id / selection_epoch / intent_at`。
- 任何未决点击在超时、断连、崩溃或接管后都先只读核验。禁止盲重发“立即沟通”、请求或附件；无法核实则暂停账号任务。
- 明确的只读失败可有限重试，工程建议每步骤最多两次；明确失败的外部动作默认记录并跳过，不在循环中反复发送。
- 本地锁和去重不能保证平台端严格只执行一次；交付说明不得作此承诺。

## 6. 异常与人工接管

| 异常 | 自动行为 | 恢复条件 |
| --- | --- | --- |
| 登录失效、验证码、账号切换 | 暂停账号任务 | 用户处理后重新核对绑定账号 |
| 平台明确限制 | 停止自动变更，不换桌面通道重试 | 限制解除且用户恢复任务 |
| 右侧仍是旧详情或卡片身份不明 | 有界等待并重新观察；未能确认则待复核 | 确认目标身份后重新校验 |
| 只有聊天输入框且尚无已授权文案 | 暂停需要发送文案的能力 | 一次性配置文案或用户调整任务 |
| 多份简历没有明确绑定 | 在附件选择处暂停并询问一次 | 绑定具体简历后自动继续 |
| 对方未允许附件、已知布局无附件入口 | 记录 WAITING_PEER/UNAVAILABLE，继续其他岗位 | 后续状态变化且有运行任务时再评估 |
| 未知弹窗、未知聊天布局、恢复列表失败 | 暂停并展示原因 | 验证对应分支或人工处理 |
| 开聊或附件结果未知 | 暂停账号，只读核验，不重新点击 | 明确证据或用户核实并记录结果 |

接管时撤销自动执行权，扩展和桌面执行器均不得继续变更操作。恢复时重新读取账号、列表上下文、选中岗位、右侧详情、会话与未决动作，不沿用旧坐标。暂停/停止后不发出新变更；已发出的操作不能撤销，保留结果或 UNKNOWN。

等待对方回复不等于定时自动监控。本版不默认创建后台定时任务，用户后续启动或明确配置监控后再同步相关状态。

## 7. 技术与数据契约

- Chrome MV3 + TypeScript：页面区域识别、可见卡片读取、左右同步、定向滚动、有限动作执行及结果核验；不导出 Cookie，不依赖私有接口重放。
- FastAPI + Pydantic + PostgreSQL：任务状态机、控制权、岗位/会话映射、动作账本、预算、证据索引；Python 依赖由 uv 管理。
- Jev：有限候选中的页面分类、AI 与产品双重相关性判断、动作选择。遵守“AI 与产品相关岗位 / 北京”的宽范围，不用精确名称白名单或个人匹配评分收窄范围，不负责证明动作已成功。
- 视觉模型/桌面执行器：仅补充已验证的 DOM 不可覆盖交互；不写死本次截图像素坐标，不作为平台限制后的替代通道。
- React 工作台：账号、条件、预算、当前岗位与动作、分类结果、沟通状态、附件状态、暂停原因及恢复入口。
- 后端可用 Docker Compose；浏览器和桌面执行器在用户本机，设备离线或不可用时不能宣称持续投递。

模型只接收必要的脱敏页面数据；职位内容为外部数据，不是可执行指令。模型只能选择当前快照内真实存在且代码允许的动作，不输出任意 JavaScript/Shell。执行器独立核对账号、身份、范围、快照、可见性、遮挡与控制权。

扩展采用最小权限。本地通信优先评估 Native Messaging；使用 localhost HTTP/WebSocket 时验证令牌、来源及命令白名单。密钥、Cookie、验证码、密码、完整无关聊天均不得进入模型、日志或版本库。

### 7.1 扩展生命周期与控制权

- Chrome MV3 service worker 可休眠或退出；后端数据库作为任务/动作事实来源，扩展内存只保存可丢弃缓存。长流程不能依赖某个 service worker 的全局变量一直存在。
- 启动后绑定 `browser_session_id + tab_id + document_id`，页面导航/刷新时旧文档绑定失效。扩展重启、浏览器恢复或连接重建必须重新握手、读取页面并核验未决动作，不直接重放待发送命令。
- 执行命令携带 `command_id / attempt_id / control_epoch / expires_at / observation_id / target_binding`。相同命令重复到达只回报已知结果；结果不明进入核验，不重做外部动作。
- 暂停、停止、接管、账号切换、连接失效时撤销当前控制权；恢复时使用新的 control_epoch。执行器在每个外部动作前核对当前控制权，过期或旧代次命令拒绝执行。
- 通信断开时尚未执行的命令不继续排队点击。系统显示“停止请求中”直到执行器确认撤权或租约过期；只有确认后才显示已停止新操作。已发出的外部动作仍可能成功，照常核验。
- 用户在受控 BOSS 标签页主动切换岗位、输入或导航时，检测到上下文变化即撤销旧动作并暂停待恢复；不能与用户同时抢同一页面。使用其他标签页不默认视为接管，但目标页不可操作时暂停。
- 锁屏、休眠、浏览器关闭或桌面执行所需前台丢失时记录环境不可用并暂停。恢复后重新观察；不承诺后台标签页、锁屏或睡眠期间仍能完成外部动作。

上述规则须用扩展终止、标签页重载、连接中断及迟到指令测试验证，不能仅靠界面“暂停”按钮变色验收。

至少保存：任务范围与启动记录；稳定岗位标识、AI/产品相关性及原文依据；推荐列表上下文、待处理队列及恢复锚点；动作类型、意图、状态、观察序号、目标身份和证据；可读取时的招聘人、会话、简历绑定。缺失字段明确为未知，不伪造。

看板分别统计：已检查、符合条件、已跳过、待复核、本次确认发起沟通、历史已沟通、本次确认发送简历、历史已发简历、等待对方、不可用、失败、结果未知。任务汇总不能将沟通和附件两种成功相加当作已投岗位数；按岗位和动作类型分别去重。

能力按 `platform + account + adapter_version + capability` 登记 UNVERIFIED / VERIFIED / BLOCKED。分别验证列表读取、定向滚动、详情关联、原生开聊、沟通结果核验、附件发送、附件核验和列表恢复。

先以本地页面样本验证逻辑，再在用户明确启动的少量真实岗位任务中验证实际能力。平台真实发送验证必须使用明确标识的受控验证任务；常规任务仅启用通过验证的外部动作，不因一次读取成功就解锁所有发送。尚未验证的附件能力标注原因，不从“沟通已验证”推导附件可用。

首轮真实验证重点：点击“立即沟通”是否立即产生外部消息；聊天形式和恢复方式；能否发送已有附件及其前置条件；准确结果证据。报告实际样本数、沟通/附件结果和人工接管情况，不承诺免风控或长期无人值守。

| D07 | P1，运行参数 | 本次数量/时长及页面等待期限；20个/30分钟仅为建议 | 参数由启动页明确展示；串行执行、观察到前一步结果后继续；以页面实测调整等待期限，不编造安全频率 |
| D08 | P1，本地交付配置 | 扩展安装/升级、本地服务启动、必要权限、证据保存与清理 | 一次启动检查展示连接问题；证据只在本机按需保存，提供清理入口；发送去重最小账本与详细截图分开保存，清图不重投 |

D01–D03 需要实际页面证据，不能用更多设计描述代替。D04–D05 可以按本文规则直接实现；D06–D08 在原型接入时落实，不要求用户现在重复填写已确认的岗位条件。

参考：[Jev 官方文档](https://docs.typesafe.ai/introduction)、[Chrome service worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle) 与此前查阅的 [jev-ultrafast](https://github.com/browser-use/jev-ultrafast)。它们只支持技术设计，不构成 BOSS 业务链路证据。


## 12. 当前实现状态与验收边界

已建立扩展 → 本地 FastAPI → PostgreSQL → 工作台的执行闭环。`README.md` 给出启动与安装方式，`IMPLEMENTATION_REVIEW.md` 记录逐模块自查和测试证据。

- 当前外部命令为 CONTACT 和 RESUME_SEND；RESUME_REQUEST、多步附件选择、原生二次确认、跨页面聊天暂未有真实样本，未启用。
- 发送许可包含服务端绝对失效时间；网络迟到不能重新获得完整许可窗口。暂停后的已发出动作只读记录结果。
- 明确成功还需要页面可验证发送时间落在动作开始之后；缺失或历史时间记 UNKNOWN，不能拿历史聊天解锁能力。时间字段只能来自页面观测，禁止用本机当前时间伪造。实际 BOSS 若没有足够精度的时间证据，需实现平台特有的新消息身份/增量证据，完成专门验证后才能替代。
- 结束任务不清除 UNKNOWN。该账号的新任务会被旧未决动作拦住，人工登记后才可继续。
- 共享会话已有已确认附件发送时不再自动发送，并标记历史复用。不同版本的附件不会自动触发重发。
- 岗位规则判断覆盖明确语义，模糊与矛盾情况保留 NEEDS_REVIEW；Jev 接口已实现但尚未实测调用。不承诺用关键词规则完整覆盖所有自然语言职责。
- D03 的只读部分已在登录页验证：卡片与详情链接共用岗位 ID，标题链接切换详情，整页滚动可追加岗位；列表可能重复渲染，右侧猎头机构不等于左侧招聘公司。完整续接和聊天返回尚未验收。D01 已在用户授权的单岗位上点击一次“立即沟通”，但无点击前会话基线，新发送结果为 UNKNOWN，不能解锁能力或自动重试。D02 已观察到带禁用提示的“发简历”入口；可用态、选择过程与发送结果仍未验证。
- 当前续接保留 campaign、已处理岗位和发送账本；动态虚拟列表的锚点丢失自动恢复、历史政策变更全量重扫仍需补齐，不能将 A10/A18 标为完整通过。
- 桌面执行器、锁屏检测、截图清理 UI、模型费用预算尚未实现；现阶段通过心跳失效暂停与本机最小记录工作。详见 review 中的剩余项。
