# 打包扩展并提交 Chrome 网上应用店

本文只描述当前仓库里已经存在的构建结果和 Chrome 网上应用店公开流程。商店结账金额、必填图片和审核结论以 [开发者信息中心](https://chrome.google.com/webstore/devconsole) 当时页面为准。

当前版本还不能直接上传。`extension/manifest.json` 没有 `icons`，也没有 128×128 的 PNG。商店要求安装包里带这个图标。补上图标并提高 `version` 之后，才能做第一次上传。

## 这个扩展实际做什么

名称是「Auto JB 本地求职助手」，Manifest V3。它只在用户明确启动后，于已打开的 BOSS 或猎聘职位页点击一次沟通按钮，并把岗位身份、点击回执写到用户自己电脑上的 `http://127.0.0.1:17830`。它不把数据发到项目作者的服务器，也不代替用户登录招聘网站。

权限和用途：

| 权限 | 代码里的用途 |
| --- | --- |
| `storage` | 保存本机配对后的设备令牌、任务选项和诊断信息 |
| `tabs` | 在弹窗里找出当前打开的职位标签页 |
| `debugger` | 只在已配对的猎聘职位流程里发送一次真实鼠标按下和松开，用完立即 `detach` |
| `http://127.0.0.1:17830/*` | 调用本机账本，以及打开本地样本页 |
| `https://www.zhipin.com/*` | 读取指定 BOSS 职位页并点击一次「立即沟通」 |
| `https://www.liepin.com/*` | 打开指定猎聘职位明细，并点击右上角一次「聊一聊」 |

内容脚本匹配的是 `https://www.zhipin.com/*`、`https://www.liepin.com/zhaopin/*` 和 `http://127.0.0.1:17830/fixture*`。

## 打成商店要求的 ZIP

商店要的是压缩包根目录直接放 `manifest.json`，不能先套一层 `extension/` 或 `dist/` 文件夹。本仓库的工作台下载接口就是按这个结构打包的。

在项目根目录执行：

```sh
npm run build
rm -f auto-jb-extension.zip
(
  cd dist/extension &&
  zip -r ../../auto-jb-extension.zip . -x '*.DS_Store'
)
unzip -l auto-jb-extension.zip
```

`unzip -l` 的第一批路径必须是 `manifest.json`、`popup.html`、`popup.js`、`content.js`、`worker.js`，不能是 `dist/extension/manifest.json`。

本机服务已经构建并启动时，也可以登录工作台，在「连接设置」下载 `auto-jb-extension.zip`。接口是 `GET /api/extension.zip`，内容同样是 `dist/extension` 里的文件，压缩包根目录就是这些文件。服务没找到 `dist/extension` 时会返回「请先构建扩展」。

不要把 `.env`、`node_modules`、`.venv`、`dist/web` 或整个仓库打进这个 ZIP。`*.zip` 已在 `.gitignore` 里，不要把安装包提交到 GitHub。

每次重新上传商店，都要先把 `extension/manifest.json` 的 `version` 改成比商店里上一版更大的版本，再执行上面的构建和打包。只改代码、不提高版本，信息中心会拒绝。

## 上传前还缺的文件

在 `extension/` 放一个 128×128 的 PNG，并在 `manifest.json` 增加：

```json
"icons": {
  "128": "icon128.png"
}
```

图标画布是 128×128。可用图案大约 96×96，四周各留约 16 像素透明边，PNG，在浅色和深色背景下都要看得清。改完后重新 `npm run build`，确认 `dist/extension/icon128.png` 存在，再打 ZIP。

商店信息页另外要准备这些图片，它们不放进 ZIP：

- 至少 1 张、最多 5 张截图，1280×800 或 640×400，直角、无额外白边，画面必须是这个扩展自己的弹窗或工作台。
- 一张 440×280 的小型宣传图，PNG 或 JPEG。
- 信息中心若把宣传视频标成必填，再提供一条展示真实弹窗的 YouTube 链接。1400×560 的大幅宣传图是可选的。

截图不要画上其他产品的标志，也不要宣称已经投递简历或对方已收到消息。

## 注册开发者

1. 用一个会长期查看的 Google 账号打开 [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole)。账号邮箱创建后不能直接改。
2. 同意开发者协议，并支付页面上的一次性注册费。中国在官方支持的注册地区列表里。
3. 点「Add new item」，上传 `auto-jb-extension.zip`。解析失败时，先确认 ZIP 根目录有 `manifest.json`，且文件里没有注释。

一个开发者账号公开上架的扩展数量有限制。第一次可以先选不公开，只发给测试人员。

## 信息中心各页怎么填

### 商店信息

- 名称与清单一致：`Auto JB 本地求职助手`。
- 简短说明使用清单里的 `description`：`在本机工作台授权范围内读取职位、操作页面并核验结果。`
- 详细说明写明：扩展必须配合用户自己启动的本机服务；点击只表示本机发出了一次按钮点击；会话和简历由用户在招聘网站上核对。
- 类别选「生产力」或信息中心里最接近的效率工具。不要选开发者工具，这个扩展不调试网页。
- 语言选中文（简体）。

### 隐私

单一用途可以粘贴：

> 在用户自己的电脑上，协助用户对已经打开的 BOSS 直聘或猎聘职位页逐个点击一次沟通按钮，并把点击记录保存在本机。

数据披露勾选与实际行为一致：扩展会读取职位页上的岗位标题、公司、城市、职责摘要和账号头像来源，并发送到 `127.0.0.1:17830`。它不向扩展作者、广告商或其他网站发送这些数据，也不出售数据。

隐私政策必须是一个不需要登录就能打开的网址。把下面「隐私政策」一节发布到公开网页后，把该网址填进信息中心。仓库公开后，可以使用：

`https://github.com/holyxing/auto-jb/blob/main/docs/CHROME_WEB_STORE.md#隐私政策`

权限说明可以粘贴：

> `storage` 只保存本机设备令牌和任务选项。`tabs` 只用于识别当前职位标签页。`debugger` 只在用户已配对、且当前页是设定的猎聘职位流程时附加，发送一次鼠标事件后立即断开，不读取其他网站。主机权限只包含 BOSS、猎聘和本机 127.0.0.1:17830，不请求全部网站。

`debugger` 属于敏感权限。审核会核对它是不是当前功能真的在用。不要为了以后可能的功能保留它。

### 分发

先选私人测试或未列出，而不是立刻公开。公开之后，任何人都可能安装一个仍依赖本机服务、并且会在招聘网站上点击的扩展。

### 测试说明

审核员看不到你的数据库。测试说明按这个顺序写：

1. 安装 Node.js 22、uv 和 Docker。在源码目录执行 `uv run python scripts/setup.py`、`npm ci`、`npm run build`、`docker compose up -d --build --wait`。
2. 打开 `http://127.0.0.1:17830`，用本机 `.env` 里的 `AUTOJB_ADMIN_TOKEN` 登录。不要把真实令牌写进商店说明。
3. 在工作台生成配对码，在扩展弹窗输入。弹窗应显示「已配对 · 本机执行」。
4. 打开 `http://127.0.0.1:17830/fixture`。这个本地样本不会联系招聘方。选择该页后，可以先点「只读取与判断」。
5. 真实 BOSS 或猎聘点击会作用于审核员自己登录的招聘账号。没有测试账号时，说明只验收本地样本页，不要要求审核员在生产招聘账号上点击。

如果审核员无法运行本机服务，扩展会表现为未配对、按钮灰色。这是当前架构的限制，不是商店页面能单独修好的。

## 提交和发布

上传并填完必填项后提交审核。带 `debugger` 和招聘网站主机权限的扩展，审核通常比普通扩展更慢。审核通过后，信息中心会给一段发布窗口；过期未发布会退回草稿，需要重新提交。

被拒后按邮件里的具体条款改清单、说明或权限，提高 `version`，重新打包再传。不要用同一版本号覆盖。

## 隐私政策

Auto JB 本地求职助手由安装它的用户在自己的浏览器和自己的电脑上运行。

扩展读取用户当前打开的 BOSS 直聘或猎聘职位页，包括岗位标识、标题、公司、城市、职责文本，以及用于识别当前登录账号的页面头像或名称来源。用户启动任务后，扩展会在该页点击一次沟通按钮。猎聘流程使用 Chrome `debugger` 发送这次点击，随后断开调试器。

这些内容只通过 `http://127.0.0.1:17830` 写入用户本机的工作台和数据库。扩展作者不运营接收这些数据的服务器，不把数据用于广告，也不向第三方出售或转让。

配对码和设备令牌只用于让这个浏览器连接用户自己的本机服务。设备令牌保存在扩展的本地存储中。本机 `.env` 里的管理员令牌和数据库密码不在扩展里，也不应写入商店材料。

用户可在 `chrome://extensions` 移除扩展。移除扩展不会自动删除本机数据库里已经写下的岗位账本；删除账本需要用户自己处理本机 Docker 数据卷。

招聘网站账号、会话内容和简历仍由相应网站按它们自己的规则处理。本扩展不声明已经送达消息或已经投递简历。
