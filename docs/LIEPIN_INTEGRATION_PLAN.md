# 猎聘接入与验收状态

## 决策与目标

在现有 Chrome MV3 扩展和本机 FastAPI/PostgreSQL 服务内增加 `liepin` 平台适配器，不重写第二个扩展。复用配对、任务预算、暂停/接管、命令账本、同账号串行、跨批次去重和“点击结果未知不重试”；将 BOSS 页面解析与弹层规则留在 BOSS 适配器，猎聘单独实现页面识别、卡片读取、翻页和“聊一聊”动作。

本阶段任务完成点与 BOSS 对齐：扩展对一个合格、未沟通过的岗位执行一次“聊一聊”点击，记为 `CLICKED`，会话、默认招呼和简历状态由用户在猎聘人工确认。猎聘页面另有“投简历”入口，但不属于此次“聊一聊”自动任务；不能把 `CLICKED` 记作简历已投递。

## 已观察事实与范围

- 用户给出的 `https://www.liepin.com/zhaopin/?...&key=ai产品经理&...` 当前展示全国结果，含北京以外岗位。2026-10-02 在登录页面手动选择“北京”后，URL 出现 `city=010&dq=010`，结果显示“ai产品经理·北京”。`ckId`、`skId`、`fkId` 随页面操作变化，不作为固定入口条件。
- 列表包含猎头职位 `/a/<id>.shtml` 与企业直招 `/job/<id>.shtml`。稳定岗位键应含平台、路径类型和 ID；不能用行号、职位名或招聘人名字去重。
- 用户截图中的高亮卡片按钮为“继续聊”，表明该卡片不是新的“聊一聊”目标；需要跳过。岗位卡片可能仅在指针移入后露出按钮，按钮存在、可见、唯一且文字精确匹配时才能操作。未知按钮或弹层暂停。
- 沿用此前求职范围：北京、实际岗位与 AI 和产品工作相关，薪资、职级、经验不限。搜索词只是候选来源，不替代岗位判断。猎聘未设置北京筛选时只读提示用户切换；即使已筛选北京，逐卡仍要核对城市。

## 端到端流程

1. 用户在扩展选择“猎聘”，打开或确认北京搜索页；扩展只读确认登录账号的稳定标识、`key=ai产品经理`、北京筛选、列表和页码。账号只有显示名而无稳定标识时停止自动点击。
2. 每页读取岗位链接、标题、城市、公司、操作按钮状态。需要详情职责才能判断而列表证据不足时标记 `NEEDS_REVIEW`，不点击。点击岗位行或读取详情时，不得触发“聊一聊”或“投简历”。
3. 对 `INCLUDE` 岗位先查同一猎聘账号与岗位键的历史 CONTACT 命令和状态；已有 `CLICKED`、`UNKNOWN` 或页面明确“继续聊/已沟通”的岗位跳过且不消耗新岗位预算。
4. 对唯一可见的“聊一聊”按钮先持久化意图，再领取短时单次许可；重新核对账号、页面、岗位键、城市、标题、按钮状态、无遮挡和预算后，以浏览器真实指针事件点击一次。悬停只用于显示按钮；点击前必须绑定同一卡片 ID，不得以 DOM 下标推断归属。
5. 点击后必须观察到“我的沟通”面板或同卡片按钮变成“继续聊”，才记 `CLICKED` 并进入下一岗；这仍不证明消息或简历送达。点击前可明确断定未发出点击时记失败并暂停；点击后无响应或回执不明记 `UNKNOWN`，暂停且绝不自动重试。同一账号每次点击后至少间隔 5 秒。
6. 当前页处理完成后使用猎聘原生分页进入下一页，记录页码与已见岗位键；页码、列表或 URL 不符时暂停。达到岗位数、时间、最后一页或连续无新岗位时结束。用户暂停或人工操作页面立即停止新外部动作。

## 模块边界

| 模块 | 复用 | 猎聘新增 |
| --- | --- | --- |
| Chrome 扩展 | 配对、弹窗、命令执行器、账本通信 | `liepin.com` 权限、搜索 URL 校验、卡片/分页/按钮适配器、平台切换文案 |
| 本机服务 | 账号级串行、预算、命令租约、`UNKNOWN`、去重和 5 秒间隔 | `liepin` 来源校验、平台能力门禁、猎聘岗位键/分页状态 |
| 岗位判断 | 北京与 AI 产品规则 | 猎聘列表/详情字段映射；证据不足维持 `NEEDS_REVIEW` |
| 测试 | 单元、后端状态机、本地浏览器 E2E | 猎聘静态样本与现场只读校准；“继续聊”跳过、两类 URL、分页、弹层、重复点击回归 |

## 上线验收

- G0：已在真实登录页核对北京筛选、账号、两类岗位 URL、列表及原生下一页入口。列表不再悬停露出“聊一聊”；点击职位标题打开明细页后再点右上角“聊一聊”。
- G1：单元、后端与本地浏览器样本已覆盖真实鼠标悬停、浏览器级可信点击、两岗连续响应、已聊/异地跳过、已知沟通浮层关闭、5 秒节流与去重；无响应时暂停。最终构建的 BOSS/猎聘浏览器回归 3 项均通过。
- G2：真实账号旧版批次共有 15 个不同岗位留下 `liepin-click-v1` 的 `SUCCEEDED` DOM `.click()` 回执。用户观察到部分岗位只显示按钮、未打开沟通；这些记录不能视为实际沟通证据，保留去重并人工核对。2026-10-02 本机账本的猎聘 CONTACT 记录另有 2 条真实点击并观察到页面响应的成功、2 条真实点击但未观察到响应的 `UNKNOWN`、2 条旧逻辑将点击前遮挡记为 `UNKNOWN`。这些未知记录均不可自动重试。已加入按钮预悬停复核、最长 5 秒的点击后观察和点击前无效果分类；修复后的真实页面效果尚未再验证。
- G3：从扩展启动小批次后逐条检查账号、岗位键、悬停按钮和点击回执；确认“继续聊”跳过、已知浮层关闭、翻页不串页后再提高预算。验证码、限流或未知弹层都交人工处理。

## 待校准点

当前代码不读取私有接口，也不绕过猎聘校验；扩展的真实悬停与点击依赖 Chrome `debugger` 权限。该权限在浏览器层面可读取和控制标签页，本项目只对设定的猎聘职位页发送鼠标移动、按下与松开事件并立即断开，安装时须明确告知用户。真实页面仍需验证逐卡按钮归属、浮层收尾、翻页后的稳定性；页面响应不证明消息或简历送达。
